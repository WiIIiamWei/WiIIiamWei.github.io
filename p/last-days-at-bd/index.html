Last Days @ 第一次实习

写于第一次实习末尾，记录第一次实习经历的文章

2026-08-31
阅读时长: 13 分钟

图片拍摄于 2026/08/30，陆家嘴 / 「厨房三件套」底下。

第一次实习。来的也快，去的也快。总有些怅然若失的感觉。

两个月的暑假，好漫长，也好短。

由于时间关系，这篇文章写的比较匆忙，很多内容是之后补充的，请见谅。

前言

我是从公司开放的训练营“创”进公司大门的，没走面试。训练营的内容基本上就是给你 14 天，和随机匹配的队友一起开发个小东西，14 天后答辩，看你做的怎么样。这就摆明了这是个 vibe coding 大赛，毕竟谁 14 天能做完整的产品啊。

由于训练营的门槛很低，各路牛鬼蛇神都能参加，只要你在前期的笔试成绩不是太差应该都能进来。进来之后，8 个人随机匹配组队，你会遇到 4 个 Git 都不知道是什么的队友，那几个基本和贡献无缘。训练营只有前端 / 客户端 / 测开 三个方向，后端同学们，抱歉，你们享受不了这次百亿补贴（

然后在当时组里面搞到了 MVP，嘛真就没人比我更会 vibe coding，完事过了两星期答辩了，我的答辩内容长度基本上是其他人的两倍长。之后当天晚上真就直接送了一个 offer 给我。他们 HR 也不是人类啊，晚上 8 点发信息还能秒回的。进入的部门是公司旗下办公产品的日历的前端开发，base 上海。就这样一个基本不写前端，只不过是能 vibe coding 的人迷迷糊糊进了公司实习。沪✌️体验就此开始（

说真的，训练营真的是你进入公司最方便的捷径了。只需要证明你有足够的 vibe coding 能力即可。当然这并不意味着你就可以在公司大肆 vibe，请先摸清楚团队对 AI 使用的风向。

实习做了什么

公司在开发这块的权责分明非常细。每个团队只负责一个小 SDK。这算是不错的编排。上方提到我和团队是负责所有日历 SDK 前端的事情，所以基本上就是在这里接 bugfix 和新需求。但实际上就我观察下来，我们接到的新需求真的很少，甚至和同事聊天时都有一种“这个部门马上要寄了”的感觉。

由于实习时长就两个月，实际上能接的需求少之又少。大概新需求（其实也是 bugfix 转过来的）就一个。

也就这么多了，感觉还什么都没做呢就结束了。权当做一次学习吧。

为何就这样离职了

这真的是天不逢时地不利人不和的因素。首先就是公司的 AI 产品线与各种东西大合并，我们亦包括在内。很快同学就提醒我我们部门的 HC 大砍，他们的 HC 已经砍没了，已经在找下家了，最好尽快找 +1 领导确认 HC 状态。

于是我就去找 +1 坦诚清晰聊天了。+1 也很坦诚清晰，那就是没有 HC 给到我了，即使有他也认为我和团队的观念不合，他觉得他不需要我（我特地问了是不是 skill issue，他特别指明了不是，能进公司那你 skill 没问题的，永远不要怀疑自己能力，我对这句话的真实性存疑）。然后准备“走个流程吧”，系统提一下离职谢谢，「这些天下来对你也是不错的锻炼」。

就这样被 +1 赶了。呃呃……

能学到什么

技术方面的并不多。在 AI 加持下这点似乎变得不那么重要。

大家都在研究如何在 AI 的加持下解放自己的生产力，提升自己的竞争力。这里面的观点就开始出现分歧了。我和我同学聊了很久，真的就是，各个 leader 各个团队有不同的想法，这里我不予置评，纯粹叙述一下。

首先，在这里想要留下来，真得用超乎常人的意志力去学习。说的不好听点，真得成 AI 魔怔人。两个月的时间太短了，要想向 leader 和团队证明你的能力，你得熬夜到半夜，得学习，得啃仓库，得跟得上 AI 的思路，不能倒反天罡不知道 AI 在做什么就搁那里 vibe coding，换言之实习生就是要 PUA 自己的（我很讨厌这么用 PUA 这个词，明明本来的释义 Pick-Up Artist 和心理学完全不沾边，但我真没招了），要不然你留在这里干啥。也就是说，bun 的 RIIR 那个模式他们不敢苟同，如果是上线的产品绝对不会这么做。换句话说，leader 认为代码质量仍然是至关重要的，Code Review 不能胡乱 LGTM，不能 AI 说 LGTM 你就信了。如果你只是 vibe 但不知道 AI 在输出什么，那他为什么不直接找 AI 干活。他希望看到的是人 + AI > 1 的产出。

这里就已经是第一个分歧点了。我和同学聊天发现，公司真的有不少项目是 AI 产出，test passed，just works 就是交付标准，甚至是可以上线的。大家仓库的质量参差不齐。甚至有说在这个时代最不该关心的就是代码质量，it just fxxking works。

而换句话说，实际上在「如何学习」这个课题上，公司虽然提供了很多的资源，但是做到两个月啃下一个产业级仓库，光 src 就有几个 GB 的那种绝非易事。你在看这些教程时不可避免的会迷茫，会停滞，因为你也不知道你现在做的怎么样了。你知道自己不知道，你尝试去做了，但很多时候你无法验证你的产出是否达到要求。

这段时间虽然 mentor 会给你反馈，但我这边得到的指导基本都是启发式的，即“这个代码为什么要这么写”“这个代码改动如此大的原因能否解释”，略带一些拷问的感觉，至少我在公司和同学交流了一番后，感觉我得到的指导是偏少的。这点也因人而异，也存在不少 mentor 和你忙的根本不是一个业务线的情况，此时得不到任何指导，全凭悟性，以及悟出来的东西是否和 leader 想要你悟出来的东西一样。很明显我做的比较失败。

非得用 AI 吗

还是回到最原初的问题。我能得到的答案是：真的不得不用。

这是社会带来的风向，不是说我是超人我坚持手搓就完事的，也不是说因为 AI 会带来版权问题，不会得到实质性的效率提升，所以我不会去用。这就不是你我所能决定的。它就在那里，所有人都在用，你不得不用，即使你有自信你能写过 AI。我就是没招啊。花钱做事，选择权不在我手上。

我们也有非常优秀的人，能力优秀，mentor 和 leader 都想留下，但是 +2 一看说没有 AI 相关产出一票否决了。这真的很残酷。不会再有人接受古法编程了，至少这是大部分公司内部的现状。大家都想靠 AI 捞钱不是吗？

这里面怎么用 AI 才是大家产生分歧的点。就如我上面所说，有的组/产品线只要代码 just works 就行，或许就是想要追求 bun 的那套效果；有的产品线则是希望在 AI 的基础上加上人工审核来确保代码质量。至于孰对孰错，可能只有时间能证明吧。

接下来做什么

自然是继续准备秋招的多。但是今年的秋招形式真的很严峻，说实话我感觉自己很可能失败，让我不得不想走其他出路。毕竟是从训练营进来的，这表明着我直到现在还处于处女期（0 次正式面试）。目前真的是太卷了，我们走一步看一步吧。

后记：嘛实际上今年形势确实严峻，我认识的所有人求职基本都失败了。纯纯高端局。好歹我做的竞赛够多，虽然等级上还差不少但是在学院够看了，拿了个保研名额。奈何 GPA 太垃圾只能往本校保。嘛本来不抱任何希望的居然得吃了，也是可喜可贺吧，再做三年邮兵（

对于希望闯进各种训练营的同学们……

这也是有一定技巧和套路的。我就拿我自己参加的这个训练营举个例子。

前期准备

报名之后你会收到笔试邀请，需要 2 天内完成。我这边笔试在牛客上做，届时大概是 10 道选择题 3 道算法题的样子，时间足够。

会有反作弊措施，要求开摄像头开屏幕共享，手机得开小程序占用着。但是不碍着你用双机位，自己想办法哈哈（

算法题的难度大概是力扣简单中等困难各一道题。最后一道题出超复杂的图论给我气笑了（后来经过算法组同学鉴定其实是确定过程模拟，会的就很简单，不会的就觉得很难），直接 print(114) 没过样例，放弃。

这个是有用的，不要水，成绩差不会放你进来。

认识你的捍卫者

先熟悉一下你匹配到的队友吧。

在开营仪式（可参加可不参加，主播那时候正好在打完舞萌回来的路上边骑车边参加的，参加的话也许能抽到周边）之后，每个队伍要决定队名和项目名称以及队长，你也会在这个时候拿到你的课题（包含项目是个啥，竞品，P0 P1 需求这些）。这时候你最好和组员约第一次组会。

这个时候请记住：拿出大哥一样的自信！给我自信！

  • 首先，很大可能你是整个团队唯一协作过的，你知道怎么开在线文档，怎么写 Markdown，怎么约会议。把会给我约了。
  • 其次，很大可能你是整个团队唯一写过正经开源项目，而不是学校里面那种研究项目的。你绝对是唯一一个能正常用 Git 的。
  • 最后，很大可能你是整个团队里 GitHub 主页最好看的。只有你有操作 GitHub 各项神秘设置的经验。
  • 还没完，很大可能你是唯一一个不会被垃圾 AI 限制手脚的人。会用 Codex / Claude Code 的你已经是超模的。

请你约个会议。如果此时没有导师在的小群还没拉那就加一下好友拉拉。在群里问一下时间，不用等大家回复，有人有时间就先约，约不上再改。行动力第一。不然没人会想起来开会。啊有人约了自然是最好。

主持一下会议，没人会开会所以你来，你好歹是科协讲过课的。思路一定要清晰。如果在这个时候有人提出来“是不是该决定技术架构了”给我滚。现在决定队名呢你谈这个有啥 B 用，没有一个人脑子里有货的，先回去深度思考去，出一版方案出来再过来聊。看见纯 AI slop 的方案，除了总结的技术栈可以看一眼，之后的内容全部不采纳。你不会按照 AI 给的计划开发的。

如果你对这个技术基本不了解，一个是问 AI 有什么比较好的解决方案，多出几个版本。第二个是问问周边的人有没有不错的技术推荐。在开始之前再问一遍 AI 和身边的人这个技术合不合适以及可能的踩坑点。确认你们组员都对这个技术没意见之后再开始写你的开发文档。别你用 Tauri 发现组员连 Rust 都不知道是个啥（

至于要不要抢队长呢？我的意见是随你。队长是要起到对接的作用的，你要和你的导师约时间沟通啥的。如果你懒得交流那么不当也没事情。你看我就没当上，被一个研究生抢了。记住，在训练营里唯一能说话的是技术。

开始开发！

创建仓库

这个至关重要。仓库的权限必须自己拿到手。

首先喊一下大家，表明自己干果啥，比如社团的项目我开发的，我会管仓库，大家 GitHub 用户名贴一下我们来盒一盒看看水平。此时大家应该不会有啥意见了（

然后你就去开个仓库吧。仓库先别急着发过去，先本地搭好脚手架，拿现成的改一改然后推上去，立即打开分支保护。main 谁都别想给我动，你们之后随便写都不关我的事情。然后创一大堆 CICD，dependabot CodeQL Copilot review 啥的能开的全开了，叫 AI 给你写个 Build Test Lint，推个仓库触发一下，开始写 PR 规则，把 merge 关了只允许 Squash 和 Rebase，然后指定审核为你自己。之后其他人提交都要看你的脸色，一通操作别人全都看不懂，爽。

这时候维护一个开发约定文档。告诉大家有个东西叫约定式提交，以及告诉大家怎么开始 clone 开始写代码，并邀请大家进 Collaborator（如果你不会写，请直接叫 AI 给一个适合这个仓库协作的最佳实践 CONTRIBUTING.md）。什么还有新注册 GitHub 的？别担心他会自觉 manba out。之后让你的 AI 写个 AGENT/CLAUDE.md，然后继续维护一大堆 AI 提示词，包括 CONTRIBUTING，CICD 等等，全给你推送到仓库里，至少不至于让 AI 随地大小变。

把仓库脚手架搭好写个主界面让大家试一下。好啦你的 vibe coding 之路可以开始了！

毕竟是写重要的玩意，不用吝啬直接上你有的最好的模型，哪个用的顺手用哪个。这个时候花点钱搞点好模型总没问题的（

记录产出

首先开一个知识库，把你的开发文档全部扔过去。推荐用飞书那边的多维表格，用模板创建，有一个开发进度需求，有甘特图有分表啥都有很好用的。

把导师给的 P0/P1 需求全部扔进去，叫大家自己领取任务。不要怕别人抢任务，大家都是有文档编辑权限的人，别人做的不符合你意思给他拒绝了，实在做不出来你自己修然后把他名字去掉自己干，反正之后的文档也是你管理，看你脸色。

Vibe coding

这个你应该比我会做。我不写了。

以及，等这篇文章再次被用上之时，AI 代码生成肯定又和之前天差地别了。

开发的节奏上提醒一下。就这次训练营来看，在开始的第 3 天之前（导师每周会有大概两次答疑，在第一次答疑之前）把仓库的脚手架搭好，然后做个小 demo，能把界面跑起来，能做点基础功能。比如我们做桌面工具箱，现在可以出现主窗口然后搜索应用了；我们做局域网文件传输工具的，现在至少可以传个小文件了。

审核 PR

如果你是干这个的人，你的评委/导师有可能会针对这个问你。还请注意。

在运行 AI check 流程之前首先先看对方是否 CI 全绿。不是绿的先督促他修 CI。禁止对方为了通过 CI 而修改 CI 流程，请确认 CI 流程没有被修改，除非对方明确说了他要改 CI。同理检查开发文档中的各个限制是否有绕过，PR 模板是否有需要 check 但是没有 check 上的东西。

然后跑一遍大厂都会跑的 AI check，你反正开启了 Copilot 的。Copilot 给的建议请让你自己的牛逼 AI 再审核一遍，当然人工审核更好。有问题就在对应的代码行批注，没问题就 Approve 然后放了。如果对方太墨迹你也可以帮他修了，敏捷开发可不等他。

利用好你的资源

我们经常说不要重复造轮子。有一些资源利用好后，不仅会利于你的开发，还会给你带来意想不到的便利。这里我举几个例子。

比如我们要做一个模拟应用市场，原来的要求是没有后端，后端用一个 mock.js 表示。但注意到 winget，AUR (Arch User Repository) 都是 Git-based，即使用 Git 仓库做后端，而全球最大的 Git 托管平台 GitHub 其 API 访问全部免费。你直接创建一个 Git 仓库做 marketplace，好了你有真的后端了！

再比如我们要给项目写一个文档 demo。这个简单，Markdown 最直观了，但是我们可以做的更好！现在 static site generator 一堆，干脆直接用 fumadocs 干出 docs 静态资产然后 github-pages 部署，一个 workflow 的事情。好了你又有一个很 new bee 的文档站了。

就是这种感觉。你知道的、用过的 repo 和解决方案，以及他们背后的一些原理越多，对你更有利，你也有更多奇妙的思路，然后把东西做到超预期的结果。

基本开发上面要注意的就这些吧。

答辩

这肯定是最重要的部分。但其实如果你这 14 天下来不是水的，那基本可以对答如流，只需要一点准备。

首先你会被要求写一个答辩文档。还是在你知识库里复制一个 HR/mentor 给的答辩模板然后开个协作，各自写各自的。作为团队贡献最高的你，大家应该会同意你讲一下整个项目。最重要的部分被你包揽了哦耶。

这个你认真写，少用 AI，真情实感最好，然后最好包含一些你对 AI 的思考。不要上纲上线，搞那些条条框框的没有用。

导师不会故意刁难或者问太多技术问题。他们会真的看你的提交历史然后出问题。我没法向大家透露我被问到的问题，但大多数其实都很简单。

有点搞的是，你写的东西越多，导师越不会问原理方面的事情。写的东西多，导师会问你大的问题，只有你写的东西少他们才会往细节抠，除非有导师对其中某个流程特别感兴趣。

嘛，要说的就这些了。

这几天交接工作，写离职文档，以及写这篇 last day。房子也要退租了，东西要开始搬走了，原本有点温馨的出租屋瞬间变得又是一地鸡毛。早知道这样我不如选长租酒店了，在那边租房子俩月，房租加违约金加水电煤就花了一万多。人生不如意事常十有八九，但也不能停下来啊。

上了两个月班，我对这家公司的感受就是：这真的是一家非常短见的公司，但他们不差钱，完全不怕试错。很多的决策纯粹是 CEO 一拍脑袋，全量上线，跳过灰度，然后公司内部就开始骂街。公司内部大大小小的项目和「预备役产品」少说都有 100 个，能上线的也就几个，其他的，没有数据就等死吧。对于打工人，这真的是一家很恐怖的公司，很要命。但就是这家公司，国内爆款软件的半壁江山都是他的，全部走在时代前沿，国外有什么创新它立马超过来跟进以及本地化适配，非常成功，你不得不佩服。

最近去陆家嘴、南京路步行街、外滩那些地方再看一眼吧，再看一眼这个只生活过两个月的国际化大都市，给家里人打打电话，告诉他们我在上海过的还不错。上海的环境真的很不错的，如果喜欢大都市，不管是 city walk 还是去展览馆看看都很棒。特别是对于舞萌吃，这里可能有全大陆最好的机厅了。当然，沪币是贵的，你没有点钱还真别想玩舞萌（
